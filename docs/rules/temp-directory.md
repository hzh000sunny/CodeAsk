# 临时目录规则

CodeAsk 的运行时、测试、调试脚本和集成验证需要创建临时文件或临时目录时，默认不得使用系统全局 `/tmp` 作为业务路径。

## 规则

- 临时目录必须放在当前用户可写的目录下，例如：
  - `CODEASK_DATA_DIR/tmp/`
  - `~/.codeask/tmp/`
  - 测试隔离数据目录下的 `tmp/`
- 如果临时文件属于某次配置测试、同步测试或 E2E 验证，必须按用途创建独立子目录，避免污染真实运行数据。
- 临时文件不能覆盖或复用项目的正式配置文件。只有用户点击“保存”或执行明确的保存动作时，才允许写入项目持久化配置。
- 临时目录创建时必须确保父目录存在，并处理清理失败的容错；清理失败不能影响已提交的业务状态。
- 文档、脚本和测试命令中的示例路径也应遵循本规则，避免写 `CODEASK_DATA_DIR=/tmp/...` 或把 `/tmp/...` 当成默认方案。

## 原因

`/tmp` 不是所有运行环境都保证可写、可执行或具备一致权限策略。桌面环境、容器、受限服务器、企业安全策略和多用户机器上，`/tmp` 可能被挂载为只读、限制执行、定期清理或被安全软件拦截。

CodeAsk 的默认行为应当依赖当前用户目录或项目数据目录，保证同一用户下可控、可清理、可追踪。
