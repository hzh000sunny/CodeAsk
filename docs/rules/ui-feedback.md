# UI 反馈规则

> 范围：跨版本规则
> 状态：Active

本文定义 CodeAsk 中通用用户操作反馈的稳定交互规则。

适用范围包括但不限于：

- 会话页面中的提示、报错、停止生成、报告生成、附件操作
- 设置页面中的保存、删除、同步、创建失败
- 特性、Wiki、问题报告等页面中的操作反馈
- 顶栏菜单、弹窗确认后的后续反馈

## 1. 设计目标

用户操作后的反馈必须：

- 明确
- 不被局部容器裁切
- 不依赖用户自己去页面某个角落找提示
- 在视觉层级上区分成功与失败

不能再出现“消息藏在卡片里、区域里、头部一闪而过”的反馈方式。

## 2. 成功反馈规则

成功反馈统一使用**页面中部的低密度轻提示浮层**。

要求：

1. 位置在页面视觉中心区域。
2. 体积轻，不遮挡主要内容。
3. 自动消失。
4. 文案简洁，只表达结果，不堆上下文细节。

示例：

- `仓库已保存`
- `LLM 配置已删除`
- `用户设置已保存`
- `已停止生成`

不允许：

- 把成功提示渲染在某个局部卡片内
- 把成功提示放在页面头部或菜单内短暂闪现
- 让用户必须滚动或切换区域后才能看到成功反馈

## 3. 失败反馈规则

失败反馈统一使用**页面中部的阻断式弹窗提醒**。

要求：

1. 位置在页面中央。
2. 使用明确的失败语义和操作结果。
3. 默认需要用户确认关闭，不能自动消失。
4. 不依赖局部容器内的红字、角标或细小提示承担主错误反馈。

示例：

- `生成报告失败：Method Not Allowed`
- `保存 LLM 配置失败：API request failed with 500`
- `Agent 运行失败：模型上下文超限`

不允许：

- 只在表单区域、面板头部、列表顶部显示一条瞬时错误
- 把失败信息放在用户当前可能看不到的局部区域
- 失败后没有主反馈，只靠浏览器控制台或网络请求排查

## 4. 允许的局部反馈例外

以下交互可以继续使用局部轻提示，而不是全局成功 / 失败反馈：

1. **微交互复制提示**
   例如：
   - 复制消息
   - 复制代码块
   - 复制 session id

   这类提示应紧贴触发点附近显示，短暂出现后消失。

2. **流程内状态展示**
   例如：
   - 正在上传
   - 正在导入
   - 正在生成

   这类信息用于展示过程状态，不等同于最终结果反馈。

但一旦流程失败，仍必须回到本文定义的全局失败反馈规则。

## 5. 工程约束

实现层必须遵守：

1. 成功与失败反馈应尽量复用统一的全局反馈层，不允许每个页面重复发明一套局部提示样式。
2. 页面内的局部提示不允许作为主要错误反馈出口。
3. 新增功能开发时，必须先判断该反馈属于：
   - 成功结果
   - 失败结果
   - 微交互提示
   - 流程状态展示
4. 如果属于成功或失败结果，默认走全局反馈规则。

## 6. 验收要求

任何涉及用户操作结果反馈的需求，在验收时至少要确认：

1. 成功提示是否位于页面中部且不会被局部容器裁切。
2. 失败提示是否以居中弹窗呈现。
3. 失败提示是否不会自动消失。
4. 成功提示是否会自动消失且不会长期遮挡内容。
5. 是否仍残留头部闪现、卡片内红字、局部区域隐藏提示等旧实现。
