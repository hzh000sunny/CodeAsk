# v1.0.2 Agent 会话产品契约

> 状态：Draft
> 版本：v1.0.2
> 目标：让 CodeAsk 默认会话回归正常 Agent 聊天，并用 Wiki、报告、附件和代码工具增强研发问题分析能力。

## 1. 产品定位

CodeAsk 不是只会“检索 Wiki 后回答”的传统 LLM Wiki。它面向垂直研发场景，把团队 Wiki、已验证问题报告、会话附件、特性元数据和代码仓库放进同一个 Agent 会话中，帮助用户通过多轮沟通逐步得到可信结论。

v1.0.2 的产品重点是修正默认会话行为：

- 用户发普通问题时，CodeAsk 应该先像正常 Agent 一样回答。
- Wiki、报告、附件和代码是增强能力，不是每轮消息都必须跑完的固定流程。
- 后端负责提供上下文、工具、边界校验和审计；模型负责判断下一步该回答、追问还是调用工具。

## 2. 用户体验原则

1. **正常聊天优先**：一句普通问题不能自动触发完整调查闭环。
2. **多轮沟通优先**：复杂问题允许逐步补充日志、环境、版本、仓库和现象。
3. **证据增强而非流程绑架**：RAG 召回只提供上下文，不替模型生成后端流程结论。
4. **特性是候选，不是前置条件**：用户不需要先知道问题属于哪个特性。
5. **代码只读默认可用**：读取代码是分析能力的一部分，但仓库和版本不明确时要追问或标注不确定性。
6. **写操作必须确认**：报告生成、Wiki 写入、删除等动作不能静默执行。
7. **UI 透明但不暴露内部流水线**：用户看到的是真实行动轨迹，不是后端固定阶段。

## 3. 默认会话行为

默认会话每轮输入遵循：

```text
用户消息
→ 轻量上下文召回
→ Prompt 策略注入
→ 模型自然回答或决定调用工具
→ 工具结果回到模型
→ 模型继续回答、追问或建议动作
```

默认不再执行：

```text
ScopeDetection
→ KnowledgeRetrieval
→ SufficiencyJudgement
→ CodeInvestigation
```

这些旧阶段的价值迁移为：

| 旧阶段 | v1.0.2 产品含义 |
|---|---|
| ScopeDetection | 候选特性上下文 |
| KnowledgeRetrieval | 轻量 RAG 召回 + Wiki/报告工具 |
| SufficiencyJudgement | 模型基于 prompt 自行判断证据是否足够 |
| CodeInvestigation | 模型可选的只读代码工具 |

## 4. Agent 能力范围

v1.0.2 默认会话可使用以下只读或建议型能力：

| 能力 | 用户感知 | 约束 |
|---|---|---|
| Wiki 搜索 / 读取 | 引用团队知识、Runbook、设计文档 | 只读 |
| 问题报告搜索 / 读取 | 引用已验证历史案例 | 只读 |
| 会话附件列表 / 读取 | 分析用户上传日志和数据 | 只读，限定当前会话 |
| 代码搜索 / 读取 | 查实现、配置默认值、错误处理路径 | 只读，限定仓库和版本 |
| 分析策略读取 | 注入全局或特性策略 | 只读 |
| 追问用户 | 请求关键缺失信息 | 需要前端展示并等待用户 |
| 报告建议 | 建议生成定位报告 | 必须用户确认后才生成 |

## 5. 前端契约

会话右侧面板从“调查进度”改为“Agent 行动轨迹”。

必须展示：

- `retrieval_context`：本轮准备了哪些候选上下文。
- `tool_call`：模型准备使用哪个工具。
- `tool_result`：工具执行结果、成功失败、警告和证据引用。
- `evidence`：可回源证据。
- `needs_clarification` / `ask_user`：需要用户补充的问题。
- `assistant_action`：模型建议的动作。

不得作为默认会话流程展示：

- `范围判断`
- `充分性判断`
- `insufficient`
- `下一步：代码调查`

附件区域继续保留在右侧面板中，和行动轨迹平级，不混入聊天内容。

## 6. 成功标准

- 普通问答可以直接得到自然回答。
- 用户不绑定特性也能提问。
- Wiki 召回不到结果时，模型可以追问、回答不确定性或选择代码工具，而不是后端强制推进。
- 代码工具只在模型决定需要时调用。
- 工具失败不会直接让整轮会话失败，而是转成模型可处理的结构化结果。
- 前端行动轨迹只展示真实发生事件。
- 旧 v1.0 orchestrator 测试仍可作为 legacy 行为通过。

## 7. 非目标

v1.0.2 不承诺：

- 多 agent 并行调查。
- 后台长任务编排。
- 代码修改、提交和 PR。
- 完整权限隔离。
- 真实工具生产数据源的全部端到端接入。
- 向量检索优化和召回排序深度治理。
