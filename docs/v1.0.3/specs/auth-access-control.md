# v1.0.3 鉴权与访问控制设计

> 状态：实现与自动化验收已完成，等待人工浏览器验收。本文记录 v1.0.3 鉴权、用户、特性管理员、附件开关、审计和真实浏览器端到端验收要求，并作为实现验收基线。

## 1. 背景

CodeAsk 当前已经支持会话、特性、Wiki、问题报告、代码仓库、LLM 配置和全局设置，但身份体系仍以浏览器自报 `X-Subject-Id` 和简化 admin cookie 为主。v1.0.3 需要补齐登录、用户、特性管理员和服务端权限校验，避免部署后任何用户都能修改特性、Wiki 或全局配置。

本版本不能破坏现有的低门槛体验：用户不登录也应该可以打开 CodeAsk，直接发起会话，并查看特性页面和 Wiki 页面。

## 2. 目标

- [x] 支持未登录访客直接发起和使用会话。
- [x] 引入数据库用户体系，支持自动注册、登录、修改用户名和密码。
- [x] 固定 `admin` 用户，支持 admin 默认初始化、改密码和环境变量兜底恢复。
- [x] 引入特性管理员，只有 admin 和被授权的特性管理员可以操作对应特性配置和 Wiki。
- [x] 全局配置仍然只有 admin 可操作。
- [x] 会话附件上传入口保留，并由 admin 全局开关控制。
- [x] 鉴权相关操作写入审计日志，便于后续排查。
- [x] 前后端都要落实权限：前端负责清晰交互，后端负责强制校验。

## 2.1 总体实现路线

采用“数据库用户 + 稳定身份 + 服务端权限守卫”的方案。

核心原则：

- 新增正式用户体系和登录 session。
- 保留匿名浏览器 ID 作为访客身份。
- 登录用户使用稳定用户 ID 作为内部关联主键。
- 用户名只用于登录、展示、搜索和添加特性管理员时的人类输入。
- 后端建立统一权限守卫，所有写操作都必须在服务端校验。
- 前端根据 `auth/me` 返回的身份和权限状态调整按钮与提示，但前端不是安全边界。
- 不引入完整 RBAC/ACL 配置系统，v1.0.3 只实现 admin、普通用户、特性管理员三层明确规则。

不采用的路线：

- 不在现有 `X-Subject-Id` 自报身份模型上简单打补丁。
- 不引入完整权限点配置和资源 ACL，以免 v1.0.3 过度复杂。

## 3. 非目标

- 不做独立注册页。
- 不做复杂组织、团队、租户体系。
- 不做细粒度到单篇 Wiki 文档的权限。
- 不做密码找回邮件、短信验证码、OAuth、LDAP 等外部身份系统。
- 不删除用户记录，避免破坏历史会话、报告和审计。
- 不做“退出其它设备”的用户自助能力。

## 4. 后端架构设计

### 4.1 模块边界

v1.0.3 后端按职责拆分，避免继续把身份和业务权限混在单个文件中。

`codeask.auth`：

- 用户登录。
- 用户自动注册。
- 登出。
- cookie session 校验。
- 活跃续期。
- 密码 hash。
- admin 初始化。
- 环境变量 admin 凭据兜底恢复。

`codeask.users`：

- 用户资料修改。
- 用户名唯一校验。
- admin 用户管理。
- 清空普通用户密码。
- 用户搜索。

`codeask.features.permissions`：

- 特性管理员授权关系。
- 特性权限查询。
- 判断当前 actor 是否是 admin 或指定特性的管理员。

`codeask.auth.guards`：

- `require_admin`。
- `require_authenticated`。
- `require_session_owner`。
- `require_feature_operator`。
- `require_feature_admin_manager`。

`codeask.audit`：

- 鉴权审计事件写入。
- admin 查询审计列表。

`codeask.settings`：

- 追加和读取会话附件上传开关。

现有 `identity.py`：

- 从“自报 subject id + admin cookie”改成“匿名浏览器 ID + 登录 cookie”的 actor 解析层。
- 只负责识别当前 actor，不承担业务权限判断。

### 4.2 数据模型

新增或调整以下数据结构。

`users`：

- 稳定 `id`，作为内部关联主键。
- `username` 唯一且大小写敏感。
- `role`：`admin` / `member`。
- `password_hash` 可为空。
- `auth_version`，用于密码变更和清空密码后让旧登录态失效。
- `last_login_at`。
- 创建和更新时间字段。

`auth_sessions`：

- 登录 cookie 对应的服务端 session。
- 存储 token hash，不存明文 token。
- 关联 `user_id`。
- 记录 `expires_at`、`last_seen_at`、`auth_version`。
- 活跃访问时续期。

`feature_admins`：

- `feature_id`。
- `user_id`。
- `created_by_user_id`。
- `created_at`。
- 对 `feature_id + user_id` 做唯一约束。

`audit_logs`：

- 如果现有审计表字段足够，则复用。
- 如果字段不足，则通过迁移补齐 v1.0.3 所需字段。

`system_settings`：

- 增加 `session_attachments_enabled` 配置键。

### 4.3 迁移策略

- 启动迁移时创建 `admin` 用户。
- `admin` 默认密码为 `admin`。
- 保留环境变量 admin 凭据作为兜底恢复手段。
- 现有 `sessions.created_by_subject_id` 不强制批量迁移，继续支持旧 subject id。
- 普通用户登录时，把当前浏览器 ID 下的匿名会话迁移到登录用户稳定 subject。
- admin 登录时不迁移匿名会话。
- 现有 `features.owner_subject_id` 保留为历史字段，不作为最终权限依据。
- 新权限以 `feature_admins` 和 admin 角色为准。

## 5. 身份与角色

### 5.1 未登录访客

未登录访客使用浏览器本地保存的匿名浏览器 ID，例如 `client_xxx`。

允许：

- 创建会话。
- 查看当前浏览器 ID 归属的会话列表、消息、行动轨迹和会话数据。
- 发送消息、中断生成、删除或重命名自己的匿名会话。
- 查看特性页面。
- 查看 Wiki 页面。
- 在本地浏览器中配置访客 LLM。
- 基于自己的会话生成问题报告草稿，并保存到某个特性的问题草稿中。
- 在全局附件上传开关开启时，向自己的会话上传附件。

不允许：

- 创建、编辑、删除或归档特性。
- 操作特性配置、仓库关联、Skill 配置。
- 操作 Wiki 树、Wiki 文档、Wiki 导入、Wiki 删除、Wiki 排序、Wiki 重建索引等写操作。
- 访问全局配置、用户管理、全局仓库管理、全局 LLM 配置。

### 5.2 普通用户

普通用户通过登录页登录。如果用户名不存在，则自动创建用户并登录；如果用户名存在，则校验密码。

允许：

- 管理自己的会话。
- 基于自己的会话生成问题报告草稿，并保存到某个特性的问题草稿中。
- 修改自己的用户名和密码。
- 管理自己的用户级 LLM 配置。
- 查看特性页面和 Wiki 页面。
- 在全局附件上传开关开启时，向自己的会话上传附件。

不允许：

- 创建特性。
- 操作特性配置和 Wiki。
- 操作全局配置。

### 5.3 特性管理员

特性管理员是某个特性上的授权用户。

允许：

- 查看所有特性和 Wiki。
- 管理自己被授权特性的名称、描述等特性配置。
- 管理自己被授权特性的仓库关联和 Skill 配置。
- 管理自己被授权特性的 Wiki 树、Wiki 文档、Wiki 导入、Wiki 删除、Wiki 排序和 Wiki 重建索引。
- 管理自己被授权特性下的问题报告。

不允许：

- 创建特性。
- 删除或归档特性。
- 添加或删除特性管理员。
- 操作全局配置。
- 新增、编辑、删除全局仓库配置。
- 管理未授权特性的配置和 Wiki。

### 5.4 Admin

`admin` 是固定用户名，不允许改名。

允许：

- 创建特性。
- 删除或归档特性。
- 管理所有特性配置和 Wiki。
- 添加或删除特性管理员。
- 操作全局配置。
- 管理全局仓库、全局 LLM 配置、分析策略、技能配置。
- 管理会话附件上传全局开关。
- 查看审计日志。
- 清空普通用户密码记录。

限制：

- `admin` 不需要被添加为特性管理员，也不应出现在添加特性管理员的搜索候选中。
- `admin` 用户名固定，不允许通过用户设置修改。

## 6. 登录、注册和密码规则

### 6.1 登录页复用注册能力

不新增注册页。登录页承担两种能力：

- 用户名不存在：创建普通用户并登录。
- 用户名存在：校验密码后登录。

### 6.2 用户名规则

- 用户名大小写敏感，`Tom` 和 `tom` 是两个不同用户。
- 登录和修改用户名时，去掉首尾空格。
- 用户名唯一。
- 修改用户名时必须做唯一校验，冲突时提示“用户名已存在”。
- 内部权限关联不直接依赖用户名字符串，而使用稳定用户 ID。

### 6.3 密码规则

- 密码大小写敏感。
- 登录和修改密码时，去掉首尾空格。
- 密码至少 6 位。
- 用户名存在但密码错误时，提示“用户名或密码错误”。
- 用户名存在但密码记录为空时，用本次输入的新密码写入密码记录并登录。

### 6.4 Admin 初始化和兜底

- 数据库初始化时默认创建 `admin` 用户。
- `admin` 初始密码默认是 `admin`。
- `admin` 密码可以在用户设置中修改。
- 保留环境变量 admin 凭据作为兜底恢复手段：当数据库 admin 密码丢失、为空或需要恢复时，可以使用环境变量凭据登录并修复 admin 身份。

### 6.5 登录态失效

- 登录使用后端签发的 HttpOnly cookie，前端不直接保存登录 token。
- 默认登录有效期为 7 天。
- 用户活跃访问时自动续期。
- 不设置固定的 30 天强制重新登录限制。
- 用户修改自己的密码后，当前浏览器继续登录，其它旧登录态失效。
- admin 清空某个普通用户密码记录后，该用户所有旧登录态立即失效。
- admin 修改自己的密码后，当前浏览器继续登录，其它 admin 旧登录态失效。

## 7. 匿名会话与登录迁移

- 未登录时，前端长期保存一个匿名浏览器 ID。
- 普通用户登录成功后，把当前浏览器 ID 下的匿名会话迁移到该登录用户。
- `admin` 登录成功后，不迁移匿名会话，避免管理员测试或排障时错误吸收访客会话。
- 迁移只针对当前浏览器 ID，不影响其它浏览器或其它匿名用户。
- 退出登录后，前端恢复到原匿名浏览器 ID；如果本地没有匿名 ID，则重新生成。
- 已经迁移到普通用户下的会话，不会在退出登录后重新回到匿名会话列表。

## 9. 特性管理员管理

特性页面新增“管理员”tab。

展示规则：

- 所有人都可以查看管理员列表。
- 只有 admin 可以看到添加和删除管理员的操作入口。
- 特性管理员和普通用户只读查看，不显示添加、删除等权限操作按钮。

添加规则：

- 只能添加已经登录过系统的用户。
- 以用户名作为输入和展示 key。
- 后端保存授权关系时使用稳定用户 ID。
- 输入框支持远程模糊搜索用户。
- 搜索候选需要过滤 `admin`。
- 搜索结果限制数量，避免一次返回过多数据打爆前端或影响展示。
- 不支持编辑授权记录，只支持添加和删除。

## 10. 用户管理

全局设置中新增 admin 专属“用户管理”区域。

第一版范围：

- 只有 admin 可见和可操作。
- 支持按用户名模糊搜索用户。
- 默认展示最近登录的一小批用户。
- 展示用户名、角色、最近登录时间、是否已设置密码。
- 支持清空普通用户密码记录。
- 不支持删除用户。
- 不允许清空 `admin` 密码，admin 改密码走自己的用户设置页或环境变量兜底恢复。

## 11. 会话附件上传开关

全局配置中新增“会话附件上传”开关。

规则：

- UI 上传入口保留。
- 开关关闭后，任何用户点击上传入口都提示“该功能已被禁用”。
- 后端也必须校验开关，禁止绕过前端直接上传。
- 开关只控制新增上传。
- 已有附件的查看、重命名、删除仍由会话所有者权限控制，不受上传开关影响。

## 12. 代码仓库权限

代码仓库权限拆为“全局仓库登记”和“特性仓库关联”两层。

全局仓库登记：

- 只有 admin 可以新增、编辑、删除全局仓库配置。
- 全局仓库配置属于系统级资源，会影响代码索引和所有特性可用的代码范围。

特性仓库关联：

- admin 可以管理所有特性的仓库关联。
- 特性管理员可以管理自己被授权特性的仓库关联。
- 特性管理员只能从已有全局仓库中选择和解除关联，不能新增或修改全局仓库本身。

## 13. 问题报告权限

问题报告分为“从会话生成草稿”和“管理已有报告”两类权限。

生成草稿：

- 未登录访客、普通用户、特性管理员、admin 都可以基于自己的会话生成问题报告草稿。
- 生成出的报告草稿可以保存到某个特性的问题草稿中，这是会话沉淀为问题报告的基本能力。
- 保存草稿时仍需要记录创建者身份。未登录访客使用当前浏览器 ID，登录用户使用稳定用户 ID。
- 一个会话仍然只绑定一篇报告；重复生成报告时覆盖该会话已绑定的报告。

管理报告：

- 查看问题报告默认开放。
- 编辑报告、删除报告、验证通过、验证不通过、移动报告归属、清理重复报告等管理操作，只允许 admin 或该特性的特性管理员。

## 14. LLM 配置权限

LLM 配置分为三类：全局配置、用户级配置、访客本地配置。

全局 LLM 配置：

- 只有 admin 可以新增、编辑、删除和设置默认。
- 没有用户级配置或访客本地配置时，会话使用全局 LLM 池。

用户级 LLM 配置：

- 登录用户可以在用户设置中配置自己的 LLM。
- 用户级 LLM 配置只允许本人查看和操作。
- 如果用户配置了自己的 LLM，会话优先使用用户自己的配置。

访客本地 LLM 配置：

- 未登录访客可以配置 LLM，但配置只保存在本地浏览器中。
- 访客本地 LLM 配置不进入后端数据库，不参与其它用户或其它浏览器的配置。
- 访客发起会话时，前端可以把本地 LLM 配置随请求传给后端，仅用于本次模型调用。
- 随请求传递的访客 LLM API Key 不允许落库、不允许写入日志、不允许写入审计 payload、不允许进入 Agent 上下文。
- 普通用户登录成功后，可以把当前浏览器中的访客 LLM 配置迁移为该用户的用户级 LLM 配置。
- admin 登录成功后，不能迁移访客本地 LLM 配置，避免管理员误吸收测试配置或访客配置。

## 15. UI 反馈规则

沿用项目现有反馈规则：

- 成功操作使用低密度、居中的轻量悬浮提醒，短时间后自动消失。
- 失败操作使用居中弹窗提醒，不能隐藏在页面头部或容器顶部一闪而过。
- 非 admin 点击“创建特性”入口时，弹窗提示“请联系管理员添加”。
- 未授权用户触发特性配置或 Wiki 写操作时，应明确提示无权限。
- 附件上传被全局开关禁用时，提示“该功能已被禁用”。

## 16. 前端页面与交互设计

### 16.1 登录页

- 复用当前登录页，不新增注册页。
- 文案调整为“登录 / 首次使用会自动创建账号”。
- 用户名默认不再强制填入 `admin`，可以保留浏览器记忆的最近用户名。
- 登录成功后刷新 `auth/me`。
- 登录成功后重置 subject-scoped 查询缓存。
- 普通用户登录成功后，触发匿名会话迁移和访客本地 LLM 配置迁移。
- admin 登录成功后，不迁移匿名会话，也不迁移访客本地 LLM 配置。

### 16.2 顶部栏

- 未登录显示“登录”。
- 登录后显示用户名、角色标识和退出入口。
- admin 可以进入全局设置。
- 普通用户进入用户设置。
- 退出登录后恢复匿名浏览器 ID。
- 退出登录后刷新会话、特性、Wiki、设置相关查询。

### 16.3 用户设置

- 登录用户显示用户名、修改用户名、修改密码、用户级 LLM 配置。
- 未登录访客显示浏览器 ID 和访客本地 LLM 配置。
- admin 用户名固定不可改，但可以修改密码。
- admin 仍可进入全局配置。

### 16.4 全局设置

- 只有 admin 可见。
- 新增用户管理区域。
- 新增会话附件上传开关。
- 继续保留全局 LLM、仓库、策略等管理入口。

### 16.5 特性页面

- 创建特性按钮保留。
- 非 admin 点击创建特性时，居中弹窗提示“请联系管理员添加”。
- 新增“管理员”tab。
- 所有人可查看管理员列表。
- 只有 admin 可添加和删除特性管理员。
- 非 admin 不显示添加和删除特性管理员按钮。
- 特性配置、仓库关联、Skill 配置等写入口，只对 admin 或该特性的特性管理员展示。
- 未授权用户如果通过异常入口触发写操作，显示无权限弹窗。

### 16.6 Wiki 页面

- 只读查看对所有人开放。
- Wiki 树三点菜单、上传、编辑、删除、排序、清空、重建索引等写入口，只对 admin 或对应特性的特性管理员展示。
- 后端仍强制校验 Wiki 写权限。

### 16.7 会话附件上传

- 上传 UI 保留。
- 全局开关关闭时，点击上传弹窗提示“该功能已被禁用”。
- 开关开启时，未登录访客和登录用户都可以上传到自己的会话。

## 18. 服务端校验原则

- 前端权限控制只负责交互体验，不能作为安全边界。
- 所有写操作必须有后端权限校验。
- 全局配置接口只允许 admin。
- 特性写接口只允许 admin 或该特性的管理员。
- 特性管理员授权接口只允许 admin。
- 全局仓库配置接口只允许 admin。
- 特性仓库关联接口允许 admin 或该特性的管理员。
- 全局 LLM 配置接口只允许 admin。
- 用户级 LLM 配置接口只允许本人。
- 访客本地 LLM 配置不落后端数据库；随会话请求传递时，只允许在本次模型调用内存流程中使用。
- 会话接口继续按会话所有者身份隔离。
- 匿名会话使用浏览器 ID 隔离，不能访问其它浏览器 ID 的会话。
- 会话附件上传需要同时满足会话所有者校验和全局开关校验。
- 从会话生成问题报告草稿时，必须校验会话所有者；管理已有报告时，必须校验特性管理员或 admin 权限。

## 19. 当前已确认决策

- 普通用户登录后迁移当前浏览器 ID 下的匿名会话。
- admin 登录后不迁移匿名会话。
- 内部权限关联使用稳定用户 ID，用户名用于登录、展示和搜索。
- 匿名用户可以查看特性页面和 Wiki 页面。
- 匿名用户可以上传会话附件，但受全局开关控制。
- admin 用户名固定，默认初始化，初始密码默认 `admin`。
- admin 密码可以修改，环境变量 admin 凭据作为兜底恢复手段。
- 特性管理员不能添加或删除特性管理员。
- 全局配置只允许 admin 操作。
- 用户管理第一版只做搜索和清空普通用户密码，不删除用户。
- 未登录访客和普通用户都可以基于自己的会话生成问题报告草稿，并保存到特性的问题草稿中。
- 问题报告的编辑、删除、验证等管理操作只允许 admin 或对应特性的特性管理员。
- 全局仓库登记只允许 admin，特性仓库关联允许 admin 或对应特性的特性管理员。
- 未登录访客可以配置 LLM，但只保存在本地浏览器中。
- 访客本地 LLM 配置允许随会话请求传给后端仅用于本次调用，敏感字段不落库、不写日志、不进入上下文。
- 普通用户登录后可以迁移访客本地 LLM 配置，admin 登录后不能迁移。
- 未授权管理按钮大部分隐藏；创建特性入口保留，非 admin 点击时提示“请联系管理员添加”。
- 审计日志纳入 v1.0.3 验收范围。

## 20. 验收原则

- v1.0.3 的所有关键能力必须实际启动前后端服务，并通过真实浏览器进行端到端验收。
- 不接受只看接口返回、只跑单测或只看代码静态推导的验收结论。
- 每一阶段的开发完成后，都要回到真实浏览器里验证交互、权限和页面反馈。
- 若浏览器验收未通过，即使单测通过也不能算完成。

## 21. 端到端验收清单

### 21.1 匿名会话

- 未登录进入系统。
- 创建会话并问答成功。
- 刷新页面后，会话仍属于当前浏览器 ID。
- 可查看特性页面和 Wiki 页面。
- 不能操作特性配置和 Wiki 写入口。

### 21.2 普通用户自动注册和登录迁移

- 输入新用户名和 6 位以上密码。
- 自动注册并登录成功。
- 登录前匿名会话迁移到该用户。
- 退出登录后恢复匿名 ID。
- 已迁移会话不再出现在匿名会话列表。

### 21.3 Admin 登录不迁移

- 匿名状态下创建会话。
- 登录 admin。
- 匿名会话不迁移到 admin。
- admin 可以看到全局配置和创建特性入口。

### 21.4 用户设置

- 普通用户修改用户名成功。
- 用户名重复时失败弹窗。
- 修改密码后旧登录态失效。
- admin 用户名不可修改。
- admin 可以修改密码。

### 21.5 用户管理

- admin 搜索用户。
- admin 清空普通用户密码。
- 该用户旧登录态失效。
- 该用户下次登录时可用新密码重新设置并登录。
- 不能清空 admin 密码。

### 21.6 特性创建和管理员

- 非 admin 点击创建特性，弹窗提示“请联系管理员添加”。
- admin 创建特性成功。
- admin 在管理员 tab 搜索用户，候选中过滤 admin。
- admin 添加特性管理员成功。
- admin 删除特性管理员成功。
- 特性管理员只读查看管理员列表，不能添加或删除管理员。

### 21.7 特性配置和 Wiki 权限

- 未登录访客和普通用户可查看特性和 Wiki。
- 未登录访客和普通用户不能看到或不能执行写入口。
- 特性管理员能操作授权特性的配置和 Wiki。
- 特性管理员不能操作未授权特性。
- admin 能操作所有特性和 Wiki。

### 21.8 仓库权限

- 只有 admin 能新增、编辑、删除全局仓库。
- 特性管理员能把已有全局仓库关联到授权特性。
- 特性管理员不能新增全局仓库。

### 21.9 问题报告

- 未登录访客可基于自己的会话生成报告草稿并保存到特性。
- 普通用户可基于自己的会话生成报告草稿并保存到特性。
- 未登录访客和普通用户不能编辑、删除、验证已有报告。
- 特性管理员可以管理对应特性的报告。
- admin 可以管理所有报告。

### 21.10 附件上传开关

- 开关开启时，匿名访客能上传附件到自己的会话。
- 开关开启时，登录用户能上传附件到自己的会话。
- 开关关闭时，上传入口保留，点击弹窗提示“该功能已被禁用”。
- 开关关闭时，后端直接请求上传也被拒绝。
- 已有附件查看、重命名、删除不受上传开关影响。

### 21.11 访客 LLM 配置

- 未登录访客可配置本地 LLM。
- 访客 LLM 配置只保存在本地浏览器。
- 发起会话时可使用访客 LLM。
- 普通用户登录后可迁移为用户级 LLM。
- admin 登录不迁移访客 LLM 配置。

### 21.12 审计日志

- 登录成功有审计记录。
- 登录失败有审计记录。
- 自动注册有审计记录。
- 修改用户名有审计记录。
- 修改密码有审计记录。
- 清空密码有审计记录。
- 创建特性有审计记录。
- 管理员变更有审计记录。
- 权限拒绝有审计记录。
- 附件禁用拒绝有审计记录。
- admin 可查看分页列表和基础过滤。

### 21.13 API 级权限

- 使用 curl 或 Playwright API 直接请求写接口，未授权必须返回 401 或 403。
- 前端隐藏按钮不能作为唯一安全措施。
