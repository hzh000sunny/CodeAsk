# 前端 UI 重构路线：设计 token 重铸 + 关键页面重组

> 状态：进行中（轨道二第一块「会话界面」已交付，见 §4.1；轨道一 token 重铸未开始）
> 版本归属：**v1.0.6**（2026-06-03 从 `docs/future/` 提升为本版 UI 主线）
> 主题：在不重写组件逻辑、不换框架的前提下，把 CodeAsk 前端从"功能可用但视觉死板"升级到"有辨识度、有生命感"的成品观感。
> 设计基调（2026-06-03 与产品负责人定型）：**ink-and-paper 黑白为底**——黑白中性为主色，颜色退成几乎静音的功能信号，氛围靠动效/阴影/字重/留白营造。详见 §4.1 与 [[feedback_visual_taste_fresh]]。
> 关联：`frontend/src/styles/globals.css`、`frontend/src/components/session/`（对话流为第一块重组对象）、`CLAUDE.md`（UI 设计须先触发 `ui-ux-pro-max` / `frontend-design`）

## 1. 背景与触发

当前会话界面（尤其对话流）被判定为"丑、死板"。展开读取源码后，确认问题既有视觉层、也有结构层，但**不需要"前端全部重写"**。

关键事实（决定了改造成本）：

- 前端样式**集中在单个 `frontend/src/styles/globals.css`（约 7225 行）**，手写 CSS，无真 Tailwind（`tailwind-merge` 仅为 className 合并工具），无 CSS-in-JS。
- **84 个组件中只有 6 个使用内联 `style={{}}`**——视觉几乎全部在 CSS class 层，不在 JSX 逻辑里。
- 已存在 `:root` 变量层（`--bg/--panel/--line/--line-strong/--text/--muted/--soft/--accent/--accent-soft/--green/--shadow` 等），但**偏薄**，大量 hex 仍硬编码散落在那 7000 行里（例如 `.message-bubble` 直接写 `#ffffff/#f3f7ff/#bfd1ff`）。

结论：**换新风格 ≠ 重写前端。** 风格杠杆点是 `globals.css` 与其 token 层；React 组件树与逻辑基本不动。全量重写属于高风险低回报，只有在换框架、上组件库或信息架构本身错误时才划算——而三栏工作台 / Wiki / 设置等结构是健康的。

## 2. 对话流"死板"的具体病因（诊断样本）

以 `frontend/src/components/session/MessageStream.tsx` + `globals.css` 的 `.message-bubble`（约 1414–1481 行）为样本：

1. **所有消息同一个盒子**：user / assistant 都套 760px 白底 1px 边框圆角卡片，堆叠成"方块墙"。成熟 agent 界面从不给助手长答案套盒子，让其作为正文自由排印。
2. **没有说话人身份**：代码有 `messageRoleLabel`（你 / CodeAsk）却未渲染——无头像、无名字、无时间，turn 之间糊在一起。
3. **流式输出是死的**：生成中只有静态"正在生成…"，无首 token 前 shimmer、无 token 流入、无闪烁光标。
4. **agent 工作轨迹被流放右栏**：检索 / 工具调用 / 证据全在 `InvestigationPanel`，与答案割裂；而这恰是代码调查 agent 最"活"的部分。
5. **空状态 / 微交互寡淡**：空态仅一行"等待输入"；操作按钮 hover 才出现；反馈条裸排。

这类"布局本身就是问题"的页面是少数（2–3 个），其余页面靠 token 重铸即可自动焕新。

## 3. 方向：双轨，不大爆炸

### 轨道一 · 设计 token 重铸（一次性，全局生效）

把 `:root` 从十余个变量扩成一套完整语义系统：

- 色彩 ramp（中性灰阶为主体 + 语义色 success/error/warning/info 仅作小面积功能信号）
- 表面层级 / elevation（panel / subtle / raised / overlay）
- 字号阶梯、字重阶梯、行高
- 圆角阶梯、间距节奏（4/8）
- **动效 token**（时长 150–300ms、ease-out 入 / ease-in 出、统一 easing）
- 主色定型为 **ink/paper 中性体系**（炭灰 `#2b2f37` 为强调实心块的主色，hover 加深 `#1b1e24`；近黑文字 + 纸白/极浅灰底 + hairline 灰线）；**不引入大面积品牌强调色**。⚠️ 早期"一条品牌强调色铺满全局"的设想已被否（先深蓝、后薄荷青均匀刷满 → "花花绿绿、视觉疲劳"），结论是**强调色只在极少数功能瞬间出现**（见 §4.1）。

因 84 个组件吃 class 层、仅 6 个碰内联样式，**重铸 token + 收编硬编码 hex 后，整个产品质感一起焕新，却不碰组件逻辑**。这是"看起来像新产品"性价比最高的一步。

### 轨道二 · 仅对"布局即问题"的少数页面做结构重组

第一块是**对话流**（已与用户对齐方向，见 §4）。其余结构性页面按影响排序，逐块推进，不一次铺满。

### 推进节奏

可分批上、随时停：先重铸 token → 全局焕新 → 再一块块重组关键页面。每批配视觉回归后再合。

## 4. 对话流重组：已对齐的方向

基调与工作轨迹位置已与用户确认：

- **基调：精炼实录。** 沿用现有 token；把"聊天气泡"改为"会自己书写的调查实录 / 案卷"隐喻。
  - 用户 turn → 右对齐紧凑小卡（本就短）。
  - 助手 turn → **去盒子**、全幅正文排印，左侧留"说话人沟槽"（CA 头像 + 名字 + 时间）。
  - 空状态 → "从这里开始 + 建议提问 + CodeAsk 能做什么"。
  - 流式生命感 → 首 token 前 shimmer、token 流入、闪烁 caret；新内容块 `fade+rise` 入场。
- **工作轨迹：内联进对话流。** 在用户问句与最终答案之间嵌入可折叠、实时刷新的竖向连接线时间线（检索 → 工具 → 证据），干完塌缩成一行摘要（"已检索 12 文件 · 调用 3 工具 ▸"）。


### 4.1 已交付（v1.0.6）：会话界面 ink-and-paper

§4 的"精炼实录"结构已落地，**配色基调定型为 ink-and-paper 黑白**（取代早期的品牌强调色设想）。纯 CSS 改动（`globals.css`），不动组件逻辑/DOM，272 测试 + lint + tsc + build 全绿。

**配色语义（最终）：**

- **炭灰 `#2b2f37`（hover `#1b1e24`）= 中性主色**：CA 头像、新建/发送/弹窗主按钮、选中会话左条 + 标题、流式 caret、进度条、空状态图标。早期纯黑 `#16181d` 被判"压抑"，统一软化为炭灰。
- **蓝 `--accent` = 唯一"agent 正在干活"的活跃信号**：仅出现在**行动轨迹**的"运行中"态——内联 `WorkingTimeline` 的运行步骤点/图标/顶部扫描线，右栏 `action-trace-card[data-status=running]` 的左条 + 呼吸动效。其余地方不出现蓝。
- **success 绿 / error 红 = 小面积功能点**（状态点/细左条），不铺色。
- 颜色不再均匀铺满任何组件；活力交给动效（头像脉冲、timeline 扫描线、运行卡呼吸、按钮微浮）、hairline 与阴影层级。

**已重塑的组件（每个按角色单独设计，非统一套色）：**

- 对话流：空状态、用户右对齐小卡、助手"说话人沟槽 + 全幅正文"、流式 caret、footer 内联操作/反馈条。
- 左栏会话列表（炭灰左条 active）、搜索聚焦、新建按钮。
- 顶栏、输入区（炭灰发送按钮 + 微浮）、右栏容器 + 运行状态卡 + 进度条。
- 右栏 `action-trace` 取证卡：纸感微浮 + hover 抬升 + 运行卡蓝色呼吸。
- 会话弹窗主按钮：`.session-workspace` 范围内改炭灰（全站 `--accent` 蓝约定不动）。

**调查轨迹：单一来源（2026-06-03 修正）。** §4 草图里曾把工作时间线**内联**进对话流（可折叠 `WorkingTimeline`：步数/工具/证据/失败指标 + live 蓝色扫描线 + `max-height:260px` 滚动贴底），与右栏 `ActionTracePanel`（「Agent 行动轨迹」）并存。但二者吃的是**同一份 `ActionTraceEvent[]`**——内联按本轮过滤、右栏全量——产品负责人判为"事件重复"。决策：**删内联、保留右栏**作为唯一轨迹来源。已移除 `WorkingTimeline.tsx`、其 `.working-timeline*` CSS、`MessageStream` 里的 `insights` prop 与前端邻接 join、以及相关测试；`insights` 仍照常流向右栏 `InvestigationPanel`。

> 复盘：§2 的诊断（"工作轨迹被流放右栏、与答案割裂"）成立，但内联**整条时间线**的代价是与右栏逐事件重复、视觉冗余。结论是工作轨迹归右栏单一承载；若日后想在对话流就近暴露"本轮干了什么"，应是**一行极简摘要**（"已检索 12 文件 · 调用 3 工具 ▸" 跳转右栏），而非复制整条时间线——此项归入轨道二后续待办。

**实现要点 / 已解决的历史问题（详见组件注释）：**

- 顺手修复：流式生成中无法向上滚动的 autoscroll bug（stick-to-bottom 仅在贴近底部时跟随）。
- **未修的历史 bug（已记录、待数据层决策）**：assistant turn 的 `turn_id` live 与 reload 不一致（live=client turn id，reload=agent turn row id，二者无存储链接），导致反馈 badge reload 后丢失。根因需后端数据模型决策，本次未动。（曾用前端邻接 join 在内联时间线侧规避，该时间线现已删除；右栏 trace 自有持久化通路，不受影响。）

## 5. 边界与约束

- **一致性优先于炫技**：复用既有 token 体系，新风格须与产品其余页面（含 OpenCode 控制台）同一套语言；不从零另开一套调色/字体造成割裂。
- **可访问性**：对比度 ≥ 4.5:1；保留可见 focus ring；图标按钮带 aria-label；`prefers-reduced-motion` 下关闭入场 / 流式动效。
- **视觉回归是硬前置**：token 重铸会触及每一个页面，必须配截图 / Playwright 对比，分批合入。
- **硬编码 hex 收编**：把散落 7000 行里的 hex 提升进 token，机械但必要。
- **设计流程**：按 `CLAUDE.md`，规划 / 评审用 `ui-ux-pro-max`，落地实现用 `frontend-design`。

## 7. 不做什么

- 不换前端框架、不引入重型组件库、不改信息架构（三栏工作台等结构保留）。
- 不一次性大爆炸重写 84 个组件。
- 不在未做视觉回归的情况下把 token 重铸直接铺向全站。
